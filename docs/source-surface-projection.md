# 原图外观投影到真实模型表面

本功能保留原图已经呈现的颜色、文字和细线，把这些像素映射到已有三维网格的可见表面。它不增加前景图片平面，不替代几何建模，不恢复原图没有展示的背面，也不是独立于光照的材质反照率恢复。

## 开启方式

先把相机、物体比例和原图轮廓校准，再在完整场景计划中明确加入：

```json
{
  "appearance_mode": "reference",
  "reference_lighting": {"tone_mapping": "none", "exposure": 1.0},
  "reference_projection": {
    "mode": "source_appearance",
    "object_ids": ["building"]
  }
}
```

`building` 必须是当前计划中根级注册资产对象的 `id`，不是 `asset_id`、文件名或 GLB 摘要。首版一次最多选4个对象，每个对象只能对应1个原图区域；该区域必须有置信度不低于0.8的原图外轮廓和已知孔洞。首版限定正交参考相机。网页仍可旋转查看或切换透视，但源投影相机始终固定在原图视角。

按原流程调用 `validate_scene_plan`、`build_threejs_scene`、`capture_scene_views`。服务端从该任务读取原始图片字节，校验SHA256，再把原生裁剪和蒙版放入不可变构建清单。不要手工修改已经生成的网页或把另一张图片塞进旧构建。

## 具体边界

- 原图裁剪必须为整数像素，不缩小、不自动配准、不自动修色。裁剪最长边4096、总像素不超过4,194,304；超限明确报错，不偷换缩略图。
- 需要不透明、方向明确的RGB来源；带旋转EXIF、透明度或含有尚未明确处理的ICC配置会被拒绝。保留原图光照，因此要求关闭再次色调映射，并把曝光固定为1。
- 投影被固定在每块网格的原始局部坐标中；旋转和拖动物体不会让文字在表面滑动。
- 用原图视角的真实场景深度、朝向和原图蒙版限制投影范围。蒙版边界内缩2像素，门洞和孔洞不投影；背面和被其他物体挡住的表面继续用原有材质。深度阈值是有限精度的启发式，不是精确可见性证明。
- 日景显示源图外观；暮色关闭原图外观投影，显示推断的材质/灯光变化，避免把已经带阴影的照片再叠加一遍光照。复位恢复原图外观。
- ID图和深度图仍来自真实几何，不读取原图颜色作为物体标签，因此表面图案不能充当几何还原的证明。
- 此版本是网页GPU表面投影，不会把原图纹理写回组件的`.blend`或独立GLB。导出网页ZIP包含必要图片与代码；独立组件GLB仍是原始组件。UV展开/贴图烘焙属于后续工作。

## 为什么必须先校准几何

错误的几何也可能在原图视角呈现相似图案，但转动后会变形。因此原图视角、近景、左右视角和灰模/ID轮廓应分别检查。投影新增三角面为0，不能提高轮廓分数或修复错误的门窗开口。

## 实际可复跑验证

新增 `.github/workflows/validate-3d.yml`，在PR更新时执行完整后端测试、运行时测试与构建，并在隔离环境安装校验过的Blender 4.2.0，运行：

```sh
python -m unittest discover -s server3d/tests -v
npm --prefix runtime3d test
npm --prefix runtime3d run build
python -m scripts3d.integration_smoke /path/to/new-evidence-directory
```

集成脚本使用真实Blender生成/形变、真实GLTFLoader和Chrome，不用生成器或浏览器替身。它保留原视角、左右视角、桌面、手机、诊断图和交互检查；新增条纹图案检查源像素方向、位置和颜色。条纹图案及组件都是合成测试样本，不是用户实际原图的重建验收。

云端无独立GPU的测试拆成 `--group standard`、`--group showcase` 和 `--group projection`，每组保留完整画质和独立证据。集成脚本允许每次捕获600秒；生产Store的捕获时间上限不在这里放宽。超时必须记录为失败，不能当作设备性能验收通过。

本轮修复了实际MCP SDK不接受工具裸`dict`结构化返回类型的问题，并将画布撤销测试与覆盖在画布上的DOM控件像素分开。通过结果以相应提交的Actions日志和产物为准，不在本说明中预先声称通过。
